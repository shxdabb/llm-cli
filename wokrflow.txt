# Architecture

The basic architecture is:

```text
Terminal
   ↓
main.py
   ↓
requests
   ↓
Gemini REST API
   ↓
JSON response
   ↓
main.py
   ↓
Terminal
```

We are NOT using FastAPI.

FastAPI would be useful if we were building our own web API/server, for example:

```text
Frontend
   ↓
FastAPI
   ↓
Python logic
   ↓
Gemini API
```

But Moonwork Phase 1 is a CLI application, so plain Python is intentional.

# Phase 1 Build Order

Start with:

* no conversation history

Before writing the code, explain:

* JSON request body

```text
  ↓

  ↓

  ↓

```

## Checkpoint 2 — User input

Wrap the API call in something conceptually like:

```python
ask(prompt: str) -> str
```

Allow input through:

* `input()`
* or `sys.argv`

The user should be able to run the CLI and provide a prompt.

---

## Checkpoint 3 — Conversation history

Add multi-turn conversation.

The important learning goal is to understand that the model does not magically remember previous requests.

We will maintain conversation history locally and send the relevant history again with each request.

Conceptually:

```text
User → message 1
Model → response 1

User → message 2
Model → response 2

User → message 3
```

The request becomes increasingly larger because previous conversation turns are included.

This should be used to understand:

* conversation history
* context window
* tokens
* input tokens vs output tokens
* why long conversations eventually become expensive/limited
* how applications manage context

Gemini's exact REST payload/role semantics should be checked against the current official Gemini documentation rather than assuming Anthropic's message format.
