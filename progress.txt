# Moonwork — Checkpoint 1 Workflow

## Goal

Make one successful Gemini API request from Python using a hardcoded prompt.

The flow should be:

```text
main.py
	↓
HTTP POST with requests
	↓
Gemini REST API
	↓
JSON response
	↓
Extract and print generated text
```

Do not add conversation history, user input, a web server, an SDK, or any framework in this checkpoint.

## Before Coding

Understand these parts of the Gemini REST API first:

1. **Endpoint:** use the Gemini `generateContent` REST endpoint for the selected model.
2. **HTTP method:** send the request with `POST`.
3. **Authentication:** read `GEMINI_API_KEY` from the environment and pass it as the API key required by the official Gemini REST API documentation. Never hardcode or print the key.
4. **Headers:** send JSON and declare the request content type as `application/json`.
5. **Request body:** send a JSON object whose `contents` contains a message with `parts`; the prompt text belongs in the part's `text` field.
6. **Response body:** inspect the returned JSON and locate the generated text through the response's candidate/content/parts structure.

Use the official Gemini REST API documentation as the source of truth for the exact model name, URL, authentication format, and JSON shape. Do not guess if the documentation differs from examples elsewhere.

## Implementation Steps

1. Confirm that `requests` is installed in the active project environment.
2. Confirm that `GEMINI_API_KEY` exists without displaying its value:

	 ```bash
	 python -c "import os; print(bool(os.getenv('GEMINI_API_KEY')))"
	 ```

3. In `main.py`, import only the small set of modules needed for this request, such as `os` and `requests`.
4. Read the API key from `os.environ` or `os.getenv`. Fail clearly if it is missing.
5. Define one hardcoded test prompt, for example: `Explain what an HTTP POST request is in one sentence.`
6. Build the request URL, headers, and JSON payload explicitly so each HTTP/JSON field is visible.
7. Send the request with `requests.post(...)`.
8. Check the HTTP status before treating the response as successful. During debugging, inspect the JSON response without printing the API key.
9. Parse the generated text from the response JSON and print only the useful answer to the terminal.
10. Keep the first implementation simple. Do not add retries, streaming, abstractions, or conversation state yet.

## Explanation After Coding

Explain every important line in `main.py`, especially:

* how the environment variable is read;
* why the endpoint uses `POST`;
* why the payload is nested under `contents`, `parts`, and `text`;
* what the headers communicate;
* how the HTTP status and JSON response are handled; and
* why the generated text is nested inside the response JSON.

Relate each Python value to the actual HTTP request or response so the implementation is understood mechanically, not just memorized.
